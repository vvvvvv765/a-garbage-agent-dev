## 三、接口（Engine）

生命周期 `start/run/stop/interrupt/is_running`；**实例 `Engine(home, workdir)`**；场景 `scenarios()` / `use_scenario(id)`；执行 `running()`（在飞工具）；
前端接线 `attach_display/set_input_source`；
安全 `set_approver/approval_mode`；用量 `usage()` / `context()`；能力 `register_capability/capabilities`；
会话 `history_events/list_sessions/load_session/new_session/current_session`；
设置 `set_thinking/thinking/effort/model/settings/status`；数据 `transcript/clear_memory`。`transcript(compact=False)` 默认纯读（不触发摘要），`compact=True` 才允许压缩；`status()` 里带 `render`（alive / healthy / error）。

### 实例路径（给桌面壳 / 多实例用）

```python
engine = Engine(home=r"Spirit\data", workdir=r"Spirit\workspace")
```

- `home`：数据根——`config.json`、`Session_Storage`、`Logs`、spill、audit 全在它下面；不传才看 `SPIRIT_HOME` / 默认规则
- `workdir`：能力 cwd + 文件相对路径 + 提示词里的工作目录；不传就看 `SPIRIT_WORKDIR` / `engine.workdir` / 启动目录
- 构造时按新根**重读配置并重绑**日志 / 会话 / 审计 / 能力依赖，不用管 import 顺序
- 子进程模式的环境变量：`SPIRIT_HOME`（数据根）、`SPIRIT_WORKDIR`（工作区）、`SPIRIT_WEB_HOST` / `SPIRIT_WEB_PORT`（网页入口，不改用户配置）
- 首次建目录、写默认 `config.json` 是**应用的事**；Spirit 只写自己要用的目录

### 模型提供商

配置里可以存多个提供商，顶层 `llm.*` 是当前生效的那一个：

```json
"llm": {
  "provider_id": "deepseek",
  "model": "deepseek-Flash",
  "base_url": "https://api.deepseek.com",
  "api_key": "",
  "api_key_env": "DEEPSEEK_API_KEY",
  "providers": [
    {"id": "deepseek", "name": "DeepSeek", "kind": "openai",
     "base_url": "https://api.deepseek.com", "api_key": "", "api_key_env": "DEEPSEEK_API_KEY",
     "models": ["deepseek-Flash", "deepseek-v4-flash"]},
    {"id": "kimi", "name": "Kimi", "kind": "openai-chat",
     "base_url": "https://api.moonshot.cn/v1", "api_key": "",
     "models": ["kimi-k3"]}
  ]
}
```

- **Key 优先用 `llm.api_key`**（界面里填），空才读环境变量；Key 会以明文写进 `config.json`
- **接口类型**：`openai` = OpenAI Responses（DeepSeek / OpenAI / Kimi / GLM / Qwen / 火山 / MiniMax / Ollama 等）；`openai-chat` = Chat Completions（硅基流动 / OpenRouter / 自定义中转等）；`anthropic` = Anthropic Messages（Claude 官方 / Anthropic 兼容中转）。BIOS 按 kind 挂对应句柄，方言代理按配置动态切换
- **思考**：Responses 用 `reasoning.effort`；Anthropic 用 `thinking.budget_tokens`；两者都跟随“深度思考”开关。Chat 接口的思考能力由模型自己决定
- **认证方式**（anthropic）：`auth: key` = `x-api-key`、`auth: token` = `Authorization: Bearer`；对应 cc-switch 的 `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`。构造客户端时隔离环境里的 `ANTHROPIC_*`，只认配置
- **Base URL**：anthropic 存之前去掉结尾 `/v1`（SDK 自己拼 `/v1/messages`）
- **设置页**：cc-switch 式两步添加（预设画廊：搜索 + 左侧分类栏 + 分组双列卡片 + 自定义配置 → 表单）、获取模型（`/api/provider/models`）、复制、设为当前、删除
- 切提供商 / 换模型后Spirit 重建客户端，**下一轮生效**
- Engine 接口：`providers()` / `save_provider(data)` / `delete_provider(id)` / `duplicate_provider(id)` / `probe_models(data)` / `activate_provider(id, model)`

### 安全（审批）

`engine.approval`：`manual` / `rules`（默认）/ `auto`。`rules` = 只读能力放行，其余询问。

“只读”由能力自己声明：`CapabilitySpec.side_effect` = `read` / `write` / `external`，`read` 和 `external` 放行。自定义能力默认 `write`（保守）；要免审批，在 spec 里显式写 `side_effect="read"`。

- `spirit`（控制台）和 `spirit-web`（浏览器）都自带审批出口，开箱即用。控制台的 stdin 由 `UserInput/Console.py` 独占：用户消息和审批答案按“读到时有 pending 与否”路由；`Ctrl+C` 在审批中拒绝并中断本轮，空闲时作废当前行，两秒内第二次退出。
- **库用法没有审批出口时，`manual/rules` 按拒绝处理**（安全默认）——只读能力不受影响。
  无头 / 自动化场景要么 `engine.set_approver(fn)`，要么把配置改成 `"approval": "auto"`。
- 每次判定写 `Logs/audit.jsonl`。

### 场景

- `Scenarios/<id>/`：`scenario.json`（能力白名单 + 安全默认值）+ `prompt.md`（提示词增量）
- 当前：`daily`（日常）/ `pentest`（渗透）；配置 `engine.scenario`
- `Engine.use_scenario(id)`：轮次边界应用；提示词下一轮生效、能力立即启停；正在处理一轮时拒绝
- 场景提示词拼在 `Prompts/engine.md` 后面，身份不变；新增场景只需加文件夹

### 不可信内容

- 外部内容能力（bash / readFile / searchFiles / fetchUrl / webSearch / processOutput / sessionSearch）的结果标记 `untrusted`
- GPU 在上下文里包裹警告；CPU 把来源记给安全子体系，后续非只读调用按 `engine.untrusted_policy` 处理（`warn` / `confirm` / `block`，默认 confirm）
- 审批卡片和 CLI 会显示“可能是提示注入诱导”；审计带来源

### 沙箱

- 文件能力只能碰工作区（绝对路径要命中工作区或 `engine.sandbox.allow_paths`）；`config.json` / 会话 / 日志永远拒绝
- bash / 后台进程：cwd 工作区、环境清掉 Key 和 `SPIRIT_*`、`HOME` 指到工作区、命令黑名单、禁止 `..`
- 越界调用在审批**之前**就被能力体系拒绝（`precheck`），不会浪费一次确认
- 设置页可开关「工作区沙箱」；细项在 `engine.sandbox.*`
- **不是 VM**；OS 级隔离留 backend 接缝

### 用量 / 成本 / 预算

- 真实 usage 从 provider 的 `completed` 事件读，不估算；每次模型请求写一条 `usage` 记录（对话 / 摘要分开标 `purpose`）
- 成本按提供商 `pricing`（元 / 百万 token）计算；没配价格就只显示 token，不显示钱
- 预算：`engine.max_turn_tokens` / `max_session_tokens` / `max_turn_cost` / `max_session_cost`（0 = 不限）——超了 CPU 停这一轮，不再请求模型
- 重复调用：`engine.repeat_limit`（默认 3；`processOutput` / `processList` 轮询豁免）
- `Engine.usage()` 返回本轮 / 会话 / 最后一次请求 / 预算；窗口取 `llm.context_window`
- `Engine.context()` 返回上一次出包的上下文构成：系统提示词 / 工具定义 / 对话消息（估算，按真实 input_tokens 校准）；窗口同样取 `llm.context_window`（设置 → 模型 → 上下文窗口，范围 1000–10000000，默认 128000）

### 停止与取消

`Engine.interrupt()` 一次取消：模型流、正在跑的工具（杀进程树）、挂起的审批、正在做的摘要。`Engine.stop()` 也会先取消。`Engine.running()` 返回当前在飞调用（名字 / 已跑秒数），供前端显示。

`bash` 是**持久 shell**：`cd` / `export` / `source venv` 在命令之间保留；取消 / 超时 / `exit` 会重开（状态丢失，结果里说明）。同一批工具里有写操作就整批串行（`side_effect`），跨批并发 bash 仍在同一把锁上串行。
